# Synthetic fixture scope

All mail text/errors/quotes/signatures are invented. `helpers.js` is a fake Office object, not a connection. Its setter is deliberately retained **only as a detector in tests**, never in shipping source. `controller.test.js` reproduces the exact stale-callback/late-target-switch ordering: **zero setter calls and unchanged body**. It also exercises absent setter capability, stale body/selection, item changes, clear/close during callbacks, concurrency, callback errors/timeouts and refused unsupported compose/client paths. There is no draft Undo: Clear discards output only.

`html.test.js` covers inert parsing, supported intermediate formatting, unsafe markup, protected boundaries, ambiguity, P/DIV/BR logical separators, split words and invalid edits. `integration.test.js` uses the actual **copied** core/dictionaries (not a substitute engine); the explicit integration command fails if the build is absent and includes actual paragraph/BR `recieve → receive` fixtures. Parent must rerun against the final reviewed core pin, including name safety at selected-fragment boundaries.

`https.test.js` generates/discards an ephemeral synthetic OpenSSL certificate and exercises the supplied loopback Python server with an explicit per-request CA. This does not modify OS/browser trust or validate an Office iframe. Node 22+, Python 3 and OpenSSL are test prerequisites.

Manual owner acceptance: trusted HTTPS `/demo.html` with synthetic text only; Correct leaves demo input unchanged and fills the read-only output; explicit Copy/manual fallback and Clear output. Then an approved real Outlook-on-web new-message sideload: the same behavior, EN/DE/both modes, selected names and protected content, P/DIV/BR, item switch/close, CSP and network checks. No message need be sent. Previous in-place/Undo browser evidence from an earlier implementation is not evidence for this new UI.

Mocks are not real host compatibility or transaction-isolation proof. Office cannot atomically bind a selection read and write; output-only removes draft writes entirely rather than claiming preflight checks fix that API limitation. Actual host/CSP/clipboard/account behavior remains untested by these local fixtures.
