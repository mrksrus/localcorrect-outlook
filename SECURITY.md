# Security policy

This is a release candidate. Report vulnerabilities privately to the repository maintainer using the host's private vulnerability-reporting facility when available; otherwise request a private channel without including message contents. Do not paste email, tokens or personally identifying data in public issues. Only synthetic fixtures should accompany a report.

Threat model: accidental draft corruption, stale async callbacks, unsupported Office clients, unsafe quoted/signature/HTML selection and unintended application-origin data disclosure. Selected markup is parsed in an inert detached document and never rendered in our page. Unsupported fragment markup/attributes are refused, not executed or silently sanitized. Body markup is inspected only in detached memory; no body HTML is inserted into the task pane. Results/errors are displayed using `textContent`. Engine output is inserted into text nodes, not treated as markup. Core contract validation rejects invalid/overlapping offsets. External hyperlinks in selected text are refused.

Snapshots and selection are reread before each write; no full-body replacement, automatic retry, send/save calls or background correction occurs. A timeout after a write has unknown outcome and locks further writes until the user inspects the draft and reopens the pane. Undo requires an unchanged body and unique reselected corrected phrase. Office has no atomic compare-and-swap selection API, so concurrent user/other-add-in edits during the final read/write gap remain a known RC risk. Do not change selection/type during an operation. Manual unmarked signatures are not reliably detectable. New HTML messages only; replies/forwards are refused.

A malicious asset host, tampered core/dictionaries, compromised dependency or compromised Office runtime is outside this protection boundary. Use HTTPS, verify ZIP hashes and source provenance, pin and review the shared core commit, restrict asset-host writes, use the supplied CSP and do not inject third-party scripts. Office.js is an externally maintained Microsoft CDN dependency without a fixed SRI hash. No claim of full offline execution or audited end-to-end isolation is made.

Public release gate: review the core pin/notices, compile and test the exact artifact, inspect ZIP contents, test with synthetic drafts in each intended real host/account, and validate manifest/sideload behavior. No live Outlook installation has yet been performed by this implementation.
